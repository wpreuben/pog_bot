# Paths of Glory Historical 캠페인 엔진 설계

## 목적과 범위

이 엔진은 실물 보드게임의 AI 상대 웹헬퍼가 사용할 규칙 기반이다. 사람 입력, 향후 AI, 기보 재생은 모두 같은 상태·합법 행동·상태 전이 API를 사용한다. 이번 단계에서는 2022 Deluxe 영문 룰북의 **Historical 캠페인**을 게임 시작부터 종료까지 진행할 수 있게 한다. AI, 기보 파서, 웹 UI, 이미지 인식은 범위 밖이다.

Historical에 필수인 룰북 5.7절 규칙은 포함한다. 특히 8장 손패(9.1.4), 참호 굴림 수정(11.2.10), 첫 CP 행동의 Guns of August 이벤트 강제, 첫 턴 Entrench 이벤트 제한, 역사 시나리오의 VP 공간과 승리 조건을 기본 규칙으로 적용한다. RTT의 The Great War 단축 시나리오, 추가 카드 20장 전체 사용, Valiant 덱 구성은 이번 완료 기준에서 제외한다. 다만 데이터 모델은 나중에 시나리오와 덱 구성을 추가할 수 있게 한다.

성공 기준은 엔진 API만으로 Historical 한 판을 합법적인 선택과 주사위 결과를 제공하면서 종료까지 진행할 수 있고, 같은 초기 조건·행동·무작위 결과를 재생하면 같은 상태와 승리 결과가 나오는 것이다. 규칙 정확성, 테스트 가능성, AI·재생 호환성, UI 편의성 순으로 판단한다.

RTT에는 `Historical`과 11턴부터 시작하는 `The Great War`가 정의되어 있다. Historical의 초기 유닛 배치는 `set_up_historical_scenario`, 덱 구성은 `set_up_standard_decks`, 턴 흐름은 `goto_start_turn` 이하의 상태 함수에 있다. RTT는 `game` 전역 변수와 문자열 상태 이름을 중심으로 작동하며, 규칙 처리와 로그·프롬프트·되돌리기·보급 경고가 결합되어 있다. `use_historical_scenario_rules()`가 항상 참을 반환하므로 이를 시나리오별 규칙 분리의 근거로 삼지 않는다. 숫자 ID와 지도 데이터는 대조에 사용하되 독립 엔진의 공개 ID와 API는 별도로 정의한다.

룰북의 턴 순서는 의무 공세 → 6개 행동 라운드(각 라운드 CP 다음 AP) → 소모 → 공성 → 전쟁 상태 → AP·CP 보충 → 카드 보충 → 턴 종료다. 전투는 선언·전투력·참호 무효화 카드·측면 공격·전투 카드·수정치·CRT·손실·후퇴·진격의 순서로 중간 선택이 생긴다. 이 두 흐름이 선택 창 설계의 기준이다.

## 접근과 기술 선택

RTT를 감싸는 방식은 빠르지만 전역 상태와 화면용 행동 형식이 API에 남는다. RTT를 점진적으로 분리하는 방식은 기존 예외를 추적하기 쉽지만 큰 단일 파일과 저작권 문제가 이어진다. **독립 엔진**을 선택한다. RTT의 데이터·동작은 검증 자료로 사용하고 공식 룰북 조항을 기준으로 규칙을 새로 구현한다.

Python 3.12 이상으로 구현하고 `uv`로 프로젝트 환경, 잠금 파일, 개발 의존성, 테스트 명령을 관리한다. 공개 자료형은 타입 힌트와 런타임 검증으로 명시하고 테스트는 `pytest`로 실행한다. 엔진은 브라우저·서버·전역 상태·외부 서비스에 의존하지 않는다. 정적 지도·카드·유닛 데이터는 버전이 고정된 구조화 파일로 두고 원본 RTT ID와 새 영문 ID의 대응 및 출처를 기록한다. 숫자 ID를 공개 계약으로 노출하지 않는다.

## 공개 API와 데이터 흐름

```python
create_game(scenario="HISTORICAL", seed=seed) -> FullGameState
generate_legal_actions(state) -> list[Action]
apply_action(state, action, random_input=None) -> Transition
get_player_view(state, side) -> PlayerVisibleState
game_result(state) -> GameResult | None
```

`FullGameState`는 직렬화 가능한 일반 값이며 함수·클로저·UI 객체가 없다. `apply_action`은 입력 상태를 바꾸지 않는다. 합법 행동은 현재 선택 창에 따라 단계적으로 생성하여 이동 경로와 다중 유닛 조합을 한 번에 모두 펼치는 폭발을 피한다. 행동은 `{ type, actor, ...payload }` 형태의 안정적인 영문 문자열과 ID만 사용한다. 예를 들어 카드 사용, 활성화, 이동, 전투 선언, 전투 카드 사용/통과, 손실 유닛 선택, 후퇴·진격, 보충 지출이 각기 별도 행동이다. 엔진은 현재 창에서 생성한 행동인지 검증하며 잘못된 행동은 상태 변경 없이 명시적 오류를 반환한다.

대표 행동 계약은 다음과 같다. `PLAY_CARD`의 `mode`는 `EVENT`, `OPS`, `SR`, `RP` 중 합법적인 값만 허용한다. 카드와 이벤트에 추가 선택이 필요하면 후속 행동으로 받는다.

```python
{"type": "PLAY_CARD", "actor": "CP", "card_id": "GUNS_OF_AUGUST", "mode": "EVENT"}
{"type": "MOVE", "actor": "CP", "unit_ids": ["GE_1_ARMY_1"], "from": "AACHEN", "to": "LIEGE"}
{"type": "PLAY_COMBAT_CARD", "actor": "AP", "card_id": "PLEVE"}
{"type": "PASS_COMBAT_CARD", "actor": "AP"}
{"type": "RECORD_DIE_RESULT", "actor": "CHANCE", "purpose": "ATTACK_FIRE", "value": 4}
```

`TransitionRecord`는 적용한 행동, 소비한 무작위 입력, 공개 결과를 순서대로 기록한다. 로그 문구는 상태 전이의 입력으로 쓰지 않는다.

현재 창은 판별 가능한 `decision` 값으로 상태에 저장한다. `decision.actor`는 `AP`, `CP`, `CHANCE` 중 하나다. 전투 중에는 `combat_context`에 참여 유닛, 공간, 카드, 수정치, 주사위, 손실, 후퇴 경로를 저장한다. 이벤트 중 추가 목표 선택도 같은 방식으로 이어 간다. `CHANCE` 창은 플레이어 결정과 구별한다. 주사위 결과는 1~6의 외부 입력 또는 주입된 RNG로 받아 전이 기록에 남기며, RNG 상태와 카드 섞기 결과도 재생 가능해야 한다. AI는 `CHANCE` 결과를 플레이어 선택으로 취급하지 않는다.

`get_player_view`는 자기 손패와 공개 정보만 제공한다. 상대 손패, 덱 순서, RNG 내부 상태는 가린다. 현재 결정자가 볼 수 있는 합법 행동만 뷰에 붙인다. 내부 전 상태는 테스트·재생·심판 기능에만 사용한다.

## GameState 구조

`GameState`에는 시나리오·데이터 버전, 턴·라운드·단계·활성 측, 현재 결정 창, VP·종료 결과, 양측 전쟁 상태와 전쟁 단계·의무 공세·RP, 국가별 참전 상태, 카드 덱·손패·버림·제거, 유닛 위치·전투력 단계·예비·제거, 공간 통제·참호·요새·공성, 보급 및 OOS 판정에 필요한 상태, 영속 이벤트·턴 한정 효과, 이동/공격 활성화 및 이미 사용한 유닛, 특수 제한 플래그, 전투 문맥, RNG 상태를 둔다. 지도 인접성·인쇄된 전투력·카드 인쇄 정보는 정적 데이터에 둔다. 보급처럼 다시 계산할 수 있는 값은 규칙상 필요한 시점에 계산하고 캐시를 쓰더라도 결과가 상태 전이에 영향을 주지 않게 한다.

정적 ID는 `BRUSSELS`, `GUNS_OF_AUGUST`처럼 영문이며 중복 유닛에는 안정적인 개별 ID를 부여한다. 화면 표시용 한글 문자열은 규칙 식별자로 쓰지 않는다.

## 규칙 모듈

| 모듈 | 책임 |
| --- | --- |
| `data`, `setup` | 지도·연결·카드·유닛 검증, Historical 초기 배치·덱·VP |
| `state`, `actions`, `engine` | 상태 계약, 결정 창, 합법 행동 생성, 상태 전이·검증 |
| `turn`, `victory` | 6개 행동 라운드, 단계 순서, 의무 공세, 전쟁 상태, VP·승리 |
| `movement`, `strategic_redeployment` | OPS 활성화, 국적·지형·연결 제한, 이동, SR |
| `combat`, `forts` | 전투 선언, 카드 창, CRT, 손실, 후퇴·진격, 공성 |
| `supply`, `replacements` | 보급 경로·OOS·소모, RP 획득과 지출 |
| `cards`, `events` | 카드 모드, 덱, 제거/버림, 이벤트 조건·효과·지속·만료 |
| `view`, `replay` | 숨김 정보 투영, 행동·주사위 기록 및 결정적 재생 |

이벤트는 공통 데이터와 카드별 핸들러로 나눈다. 핸들러는 사용 가능 조건, 선택 창, 즉시·지속 효과, 만료, 버림/제거를 명시한다. 카드가 보유한 모든 모드를 엔진이 직접 판단한다. 파일 경계는 구현 중 책임에 따라 조정할 수 있으나 공개 API와 상태 의미는 유지한다.

## 규칙 우선순위와 오류 처리

2022 Deluxe 영문 PDF를 최우선으로 한다. RTT나 한글 자료와 해석이 다르면 해당 룰북 조항, RTT 동작, 채택한 해석을 차이 기록에 남기고 회귀 테스트를 추가한다. 출처가 불분명한 단순화로 행동을 허용하거나 금지하지 않는다. 불변식은 턴/단계 일치, 카드 중복 소유 금지, 유닛의 단일 위치, 적대 유닛 동시 배치 금지, 스택·참호 한도, 숨김 정보 누출 방지다. 규칙 데이터가 불완전하면 게임 진행 중 조용히 넘어가지 않고 데이터 검증에서 실패시킨다.

## 테스트와 완료 기준

- 룰북 조항과 Historical 초기 상태를 연결한 테스트 표를 만들고 설정, 이동·활성화, 전투(CRT·요새·참호·측면·손실·후퇴·진격·전투 카드), 보급·OOS, 카드 네 모드와 이벤트, 턴 순서·RP·전쟁 상태·의무 공세·승리를 검증한다.
- 기본 덱 110장에 대해 카드 모드, 이벤트 가능 조건, 제거/버림, 지속 효과를 추적한다. 단순히 핸들러가 존재하는지만 검사하지 않고 대표 상태에서 실제 전이를 검증한다.
- 합법 행동을 하나씩 적용하는 시나리오 테스트와 시작부터 종료까지 진행하는 테스트를 둔다. 동일한 초기 상태·행동·주사위 기록 재생 결과가 동일한지 확인한다.
- 각 단계에서 양측 뷰에 숨김 정보가 보이지 않는지, 불법 행동이 원 상태를 바꾸지 않는지 검사한다.
- RTT와 다른 결과를 발견하면 공식 룰북을 대조하고 차이 기록 및 회귀 테스트로 고정한다.

Historical 캠페인의 기본 카드와 주요 예외, 모든 턴 단계·결정 창·승리 판정이 작동하고 전체 게임 재생 테스트가 통과해야 Phase 1 완료로 판단한다. 단위 모듈이나 첫 몇 턴만 작동하는 상태는 완료로 표시하지 않는다.
